# Как Sprout окажется на телефоне

Четыре ступени — от «увидеть на своём телефоне через 10 минут» до «лежит в
App Store». Каждая следующая нужна, только если предыдущей не хватает.
Не пропускай ступень 0: она ловит 90% проблем вёрстки, которых не видно
в браузере.

Главный факт, который определяет всё планирование: **Android можно собрать
где угодно, iOS — только на macOS.** Не потому что так удобнее, а потому что
Xcode есть только под Mac. Обходной путь — облачный macOS в CI, он описан
в конце.

И ещё одно, про внешний вид. Стекло в Sprout нарисовано фрагментным
шейдером, а он работает только на движке Impeller — то есть на настоящем
телефоне, iOS или Android. В браузере (`flutter run -d chrome`) такого
шейдера нет: приложение не упадёт, но панели и карточки будут выглядеть
обычным матовым стеклом, без преломления на кромке и без слияния капсул.
Поэтому смотреть, как оно на самом деле получилось, надо на телефоне —
ступень 0 ниже.

---

## Ступень 0. На своём телефоне, здесь и сейчас

### Android (5–10 минут, ничего не стоит)

1. На телефоне: **Настройки → Об устройстве → Номер сборки**, тапнуть 7 раз.
   Появится «Режим разработчика».
2. **Настройки → Для разработчиков → Отладка по USB** — включить.
3. Подключить телефон к компьютеру кабелем, на телефоне подтвердить
   «Разрешить отладку». Проверить, что компьютер его видит:

   ```bash
   flutter devices
   ```

4. Запустить:

   ```bash
   flutter run
   ```

Приложение соберётся и откроется на телефоне. Дальше работает **hot reload**:
жмёшь `r` в терминале — правки прилетают на экран за доли секунды, без
пересборки. Для доводки анимаций это основной режим работы: подкрутил
длительность кривой, нажал `r`, посмотрел на реальном устройстве.

Кабель можно убрать — `adb tcpip 5555 && adb connect <ip-телефона>:5555`
переводит отладку на Wi-Fi.

### iOS (нужен Mac, тоже бесплатно)

Подробный разбор с командами и типовыми ошибками — в отдельном файле
[на-iphone.md](на-iphone.md). Ниже коротко.

С обычным Apple ID, без платного аккаунта:

1. Открыть `ios/Runner.xcworkspace` в Xcode.
2. **Signing & Capabilities** → Team → добавить свой Apple ID.
3. Подключить iPhone, выбрать его как цель, нажать Run.
4. На телефоне: **Настройки → Основные → VPN и управление устройством** →
   доверять своему сертификату.

Ограничения бесплатной подписи: приложение живёт **7 дней**, потом нужно
переустановить; одновременно не больше 3 приложений; push-уведомления
не работают. Для разработки этого хватает.

## Ступень 1. Отдать файл другому человеку

### Android — APK

```bash
flutter build apk --release
# → build/app/outputs/flutter-apk/app-release.apk
```

Файл можно отправить в мессенджере. Получателю нужно разрешить установку
из неизвестных источников. Работает без всяких аккаунтов разработчика —
это самый быстрый способ показать приложение заказчику или другу.

APK получится крупнее нужного, потому что содержит код под все архитектуры.
Разложить по архитектурам:

```bash
flutter build apk --release --split-per-abi
```

### iOS — так нельзя

У iOS нет аналога «просто отправить файл». Любая установка на чужой
телефон требует, чтобы устройство было либо в твоём профиле разработчика
(до 100 устройств, нужен платный аккаунт), либо чтобы сборка шла через
TestFlight. Это ступень 2.

---

## Ступень 2. Тестировщикам

### Android

**Firebase App Distribution** — бесплатно, ставится по ссылке, умеет
раздавать обновления группам тестировщиков. Практичнее всего на этом этапе.

**Google Play Internal Testing** — до 100 тестировщиков, обновления
прилетают через Play Маркет. Нужен аккаунт Play Console (**$25 один раз,
навсегда**).

### iOS — TestFlight

Требует **Apple Developer Program, $99 в год**. Дальше:

```bash
flutter build ipa
```

и выгрузка через Xcode или `xcrun altool`. Тестировщик ставит приложение
из TestFlight по приглашению на почту. До 10 000 внешних тестировщиков,
сборка живёт 90 дней. Внутренние тестировщики (до 100) получают сборку
сразу, внешние — после короткой проверки Apple.

## Ступень 3. В магазины приложений

### Подготовка, общая для обеих платформ

**Иконка и сплеш-экран.** Руками их раскладывать не нужно:

```yaml
# pubspec.yaml
dev_dependencies:
  flutter_launcher_icons: ^0.14.4
  flutter_native_splash: ^2.4.6
```

```bash
dart run flutter_launcher_icons
dart run flutter_native_splash:create
```

**Версия** живёт в `pubspec.yaml` строкой `version: 1.0.0+1`. До `+` —
то, что видит пользователь; после `+` — build number, который **обязан
расти с каждой загрузкой в стор**. Одинаковый build number стор отклонит.

### Google Play

1. Аккаунт в Play Console — **$25 один раз**.
2. Создать ключ подписи и **сохранить его так, чтобы не потерять**:

   ```bash
   keytool -genkey -v -keystore ~/sprout-upload.jks \
     -keyalg RSA -keysize 2048 -validity 10000 -alias upload
   ```

   Потерянный ключ означает, что обновить опубликованное приложение
   больше нельзя — только выпускать новое, с нуля, потеряв всех
   пользователей. Play App Signing смягчает это, но ключ всё равно храни
   в менеджере паролей, а не в репозитории (`.gitignore` его уже закрывает).

3. Прописать ключ в `android/key.properties` (файл не коммитится).
4. Собрать бандл — для новых приложений Google принимает только `.aab`,
   не `.apk`:

   ```bash
   flutter build appbundle --release
   ```

5. Загрузить в Play Console, заполнить карточку: описание, скриншоты,
   иконка 512×512, feature graphic 1024×500, политика конфиденциальности
   (ссылка обязательна), возрастной рейтинг, раздел Data Safety.

**Важная деталь, на которой все спотыкаются:** если аккаунт разработчика
персональный и заведён после ноября 2023, Google требует до публикации
провести **закрытое тестирование: минимум 12 тестировщиков, непрерывно
14 дней**. Это не обходится и добавляет к плану две недели — закладывай
их заранее. У компанийских аккаунтов такого требования нет.

### App Store

1. **Apple Developer Program, $99 в год.**
2. Нужен Mac (или облачный, см. ниже).
3. В App Store Connect завести приложение с тем же bundle id, что стоит
   в Xcode (сейчас `com.ledro6.sprout`).
4. Собрать и выгрузить:

   ```bash
   flutter build ipa --release
   ```

5. Заполнить карточку: скриншоты под каждый размер экрана, описание,
   ключевые слова, политика конфиденциальности, App Privacy — раздел
   о том, какие данные собираешь.
6. Ревью: обычно 1–3 дня. Частые причины отказа — приложение выглядит
   недоделанным, есть неработающие кнопки, нет способа удалить аккаунт
   (если есть регистрация), или описание не совпадает с тем, что внутри.

## Если Mac нет

iOS собирается в облаке. Оба варианта дают macOS-машину, на которой
Xcode уже стоит:

**Codemagic** — заточен под Flutter, конфиг простой, бесплатного лимита
хватает на небольшой проект.

**GitHub Actions** с `runs-on: macos-latest` — бесплатно для публичных
репозиториев; для приватных macOS-минуты тратятся быстрее обычных.

Схема одинаковая: сертификаты и профили лежат в секретах CI, сборка
по пушу тега уходит в TestFlight. Настраивается один раз и дальше не
требует Mac вообще. Платный аккаунт Apple всё равно нужен — облако решает
вопрос железа, а не подписи.

## Сводка

| Куда | Что нужно | Деньги | Сколько ждать |
|---|---|---|---|
| Свой Android | кабель | — | 10 минут |
| Свой iPhone | Mac + Xcode | — | 20 минут, живёт 7 дней |
| APK другу | — | — | минуты |
| Firebase App Distribution | аккаунт Firebase | — | час |
| Play Internal Testing | Play Console | $25 разово | час |
| TestFlight | Apple Developer + Mac/CI | $99/год | день |
| Google Play | всё выше + карточка | $25 разово | дни, **+14 дней теста** для персональных аккаунтов |
| App Store | всё выше + карточка | $99/год | дни + ревью 1–3 дня |

**Рекомендуемый маршрут:** ступень 0 сразу, чтобы видеть анимации на
настоящем экране. Дальше APK, когда есть что показать. В сторы — когда
приложение действительно готово; там начинаются сроки, требования
к карточке и ревью, и торопиться туда незачем.
