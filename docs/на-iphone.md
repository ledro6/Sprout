# Sprout на своём iPhone

С Mac это бесплатно и занимает вечер, из которого почти всё — установка
Xcode. Никакого аккаунта разработчика за 99 $ не нужно: Apple разрешает
ставить свои сборки на свои устройства по обычному Apple ID. Ограничение
одно — **такая сборка живёт 7 дней**, потом её надо перевыпустить тем же
`flutter run`.

Смотреть надо именно на телефоне. Стекло нарисовано фрагментным шейдером,
а он работает только на движке Impeller — то есть на живом устройстве.
В браузере и, скорее всего, в симуляторе шейдера нет: приложение
запустится, но панели будут выглядеть обычным матовым стеклом, без
преломления на кромке и без слияния капсул.

---

## Что понадобится

| | |
| --- | --- |
| Mac | любой на Apple Silicon или Intel |
| Xcode | 16 или новее, из App Store, ~20 ГБ |
| Кабель | Lightning или USB-C, каким заряжаешь |
| Apple ID | обычный, тот же что на телефоне |

CocoaPods ставить не нужно: в проекте нет плагинов с нативным кодом,
Podfile'а тоже нет.

## 1. Поставить Flutter

```bash
# Homebrew, если его ещё нет
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

brew install --cask flutter
```

Дальше один раз согласиться с лицензиями Xcode:

```bash
sudo xcodebuild -license accept
sudo xcode-select -s /Applications/Xcode.app/Contents/Developer
```

Проверить, что всё на месте:

```bash
flutter doctor
```

Строки `[✓] Flutter` и `[✓] Xcode` — то, что нужно. На Android и Chrome
можно не обращать внимания.

## 3. Один раз зайти в Xcode — сказать, чем подписывать

Это единственный шаг, который нельзя сделать из терминала: подпись
привязана к твоему Apple ID, а он живёт внутри Xcode.

**Зачем это вообще.** iPhone не запускает что попало: приложение должно
быть подписано сертификатом, а конкретный телефон — внесён в профиль.
Apple разрешает делать это бесплатно, через «личную команду» (Personal
Team), которая есть у любого Apple ID. Всю возню — выпуск сертификата,
регистрацию идентификатора, добавление твоего телефона в профиль — Xcode
делает сам. Ему нужно один раз сказать, от чьего имени.

### 3.1. Добавить Apple ID в Xcode

Если ты Xcode ещё не пользовался — начни с этого, иначе на шаге 3.4
список **Team** будет пустой.

1. Меню **Xcode → Settings…** (или ⌘ и запятая). В Xcode до 14-го пункт
   называется **Preferences**.
2. Вкладка **Accounts**.
3. Кнопка **+** внизу слева → **Apple ID** → **Continue**.
4. Ввести тот же Apple ID, что на телефоне. Придёт код двухфакторной
   проверки — ввести его.
5. Слева появится твоя почта, справа — строка вида
   **Имя Фамилия (Personal Team)**. Это она и нужна.

Окно настроек закрыть.

### 3.2. Открыть проект

```bash
open ios/Runner.xcworkspace
```

Именно `.xcworkspace`, а не `.xcodeproj` — Flutter собирает через
workspace. При первом открытии Xcode пару минут индексирует проект
(внизу полоска Indexing); дожидаться её не обязательно.

### 3.3. Дойти до настроек подписи

1. Слева — навигатор проекта. Если его не видно, нажать ⌘ и 1.
2. В самом верху списка строка **Runner** с синей иконкой чертежа —
   кликнуть по ней. Ниже есть ещё жёлтая папка с тем же именем, она не
   нужна.
3. В центре откроется панель настроек. У неё слева свой узкий столбец с
   заголовками **PROJECT** и **TARGETS**. Если столбца не видно, его
   разворачивает кнопка в левом верхнем углу этой панели — либо там
   просто выпадающий список с именем текущего таргета.
4. В разделе **TARGETS** выбрать **Runner** — не RunnerTests.
5. Сверху ряд вкладок: General, **Signing & Capabilities**, Resource
   Tags, Info, Build Settings… Открыть **Signing & Capabilities**.

### 3.4. Собственно подписать

Под названием вкладки есть ещё один ряд: **All / Debug / Release /
Profile**. Это конфигурации сборки, у Flutter их три. Оставь **All** —
тогда настройка ляжет сразу на все, и `flutter run --release` потом не
попросит повторить.

1. Галочка **Automatically manage signing** — включить. Если Xcode
   переспросит («Enable automatic signing?»), согласиться.
2. Выпадающий список **Team** — выбрать **Имя Фамилия (Personal Team)**.

Всё. Через несколько секунд под полями должно появиться примерно это:

```
Provisioning Profile    Xcode Managed Profile
Signing Certificate     Apple Development: твоя@почта
```

Красных надписей быть не должно. Если есть — таблица в конце раздела.

macOS может попросить пароль от связки ключей («codesign хочет получить
доступ…»). Ввести пароль от Mac и нажать **Всегда разрешать**, иначе он
будет спрашивать на каждой сборке.

### 3.5. Если ругается на занятый идентификатор

Выглядит так:

```
Failed to register bundle identifier
The app identifier "com.ledro6.sprout" cannot be registered
to your development team because it is not available.
```

Значит, это имя уже занято чужим аккаунтом — идентификаторы Apple
регистрирует глобально. Лечится в этом же окне: поле **Bundle
Identifier** прямо над Team, поменять на любое своё, например
`com.твояфамилия.sprout`. Латиница, точки, без пробелов. Xcode
перевыпустит профиль сам.

На код это не влияет: идентификатор нигде в Dart не используется, он
нужен только системе, чтобы отличать приложения друг от друга.

### 3.6. Закрыть Xcode и вернуться в терминал

Собирать из Xcode не нужно — дальше всё делает `flutter run`. Xcode
понадобился ровно затем, чтобы записать выбор в проект.

И он его действительно записывает: после этого шага `git status` покажет
изменённый `ios/Runner.xcodeproj/project.pbxproj` — туда добавилась
строка `DEVELOPMENT_TEAM` с идентификатором твоей команды. Это нормально.
Коммитить не обязательно: закоммитишь — второй раз шаг делать не
придётся, не закоммитишь — просто повторишь на новой машине.

### Что делать, если…

| Что видишь | Что это значит | Что делать |
|---|---|---|
| Список **Team** пуст или в нём только «None» | Apple ID не добавлен в Xcode | Шаг 3.1 |
| `No signing certificate "iOS Development" found` | Сертификат ещё не выпущен | Убедиться, что Team выбрана, подождать 10–20 секунд. Помогает снять и заново поставить галочку Automatically manage signing |
| `Failed to register bundle identifier` | Имя занято | Шаг 3.5 |
| `Signing for "RunnerTests" requires a development team` | Xcode пытается подписать ещё и тесты | Выбрать в TARGETS **RunnerTests** и указать Team там же. На `flutter run` это не влияет, но мозолит глаза |
| `Your account does not have permission to create...` | Вошёл рабочим Apple ID с ограничениями | Войти личным |
| `Maximum App ID limit reached` | Личная команда даёт 10 идентификаторов в неделю | Взять тот, что уже регистрировал, или подождать |
| `Unsupported OS version` | iOS на телефоне новее, чем знает Xcode | Обновить Xcode из App Store |

Ограничения бесплатной подписи, чтобы потом не удивляться: одновременно
не больше **трёх** своих приложений на телефоне, сборка живёт **7 дней**,
push-уведомления не работают. Для «посмотреть и потрогать» этого хватает.

---

## 4. Подключить телефон и доверить сертификат

1. Воткнуть кабель, на телефоне нажать **Доверять этому компьютеру**.
2. На iOS 16 и новее включить режим разработчика:
   **Настройки → Конфиденциальность и безопасность → Режим разработчика**,
   включить, телефон перезагрузится.
3. Проверить, что Flutter его видит:

   ```bash
   flutter devices
   ```

---

## 5. Запустить

```bash
flutter run
```

Первая сборка идёт долго — минут пять-десять, дальше секунды.

При **первом** запуске приложение упадёт сразу после установки с
сообщением про недоверенного разработчика. Это нормально и лечится один
раз: **Настройки → Основные → VPN и управление устройством** → выбрать
свой Apple ID → **Доверять**. После этого запустить `flutter run` снова.

Пока команда работает, нажатие `r` в терминале перезагружает интерфейс за
доли секунды — удобно, если захочешь подвигать цифры в анимациях.

### Чтобы судить о плавности

```bash
flutter run --release
```

Обычный `flutter run` — отладочный: он медленнее, и на шейдере это
заметно. Плавность оценивай на release-сборке, а hot reload — на обычной.

## Что стоит потрогать

- **Кнопка комнаты** под приветствием. Панель не появляется готовой —
  она вытекает из кнопки: тот же прямоугольник стекла меняет размер и
  скругление, пункты проявляются друг за другом. Ткни второй раз, не
  дожидаясь конца, — движение подхватится с текущей скоростью, а не
  начнётся заново.
- **Переключение вкладок** внизу. Подложка вытягивается по ходу движения
  и собирается на месте. Быстро потыкай по разным вкладкам — увидишь,
  как она тянется.
- **Лупа справа.** Раскрываясь, она наезжает на таб-бар, и в момент
  сближения между капсулами натягивается перемычка — они стекаются в
  одну каплю. Это то самое, ради чего форму стекла считает шейдер.
- **Долгое нажатие на карточку.** Она уходит вглубь, и блик проезжает по
  кромке — свет сдвигается вместе с нажатием.
- **Карточка «Пр» с красным свечением.** Оно медленно дышит. Если
  включить **Настройки → Универсальный доступ → Движение → Уменьшение
  движения**, пульсация выключится.
- **Кромка любой панели** на фоне узора: узор под стеклом должен
  подламываться у самого края. Это преломление, и в браузере его нет.

## Через 7 дней

Сборка перестанет запускаться — это ограничение бесплатной подписи, а не
поломка. Подключить кабель, `flutter run`, снова 7 дней.

Если надоест перевыпускать или захочется дать приложение кому-то ещё —
это уже TestFlight: аккаунт Apple Developer 99 $ в год, сборки живут 90
дней и ставятся по ссылке без кабеля. Как туда попасть — в
[на-телефон.md](на-телефон.md), ступень 2.

## Если что-то пошло не так

| Что видишь | Что делать |
| --- | --- |
| `Unable to find a destination` | Телефон не разблокирован или не нажато «Доверять». Разблокировать, переткнуть кабель |
| `Failed to register bundle identifier` | Идентификатор занят кем-то другим. Поменять Bundle Identifier в Xcode (шаг 3) |
| `Untrusted Developer` на телефоне | Настройки → Основные → VPN и управление устройством → Доверять |
| `Signing for "Runner" requires a development team` | Не выбрана Team в Xcode, шаг 3 |
| Режим разработчика не появился в настройках | Он показывается только после первой попытки установки. Запусти `flutter run`, потом ищи пункт |
| Стекло выглядит просто размытым | Смотришь в симуляторе или в браузере. Нужен живой телефон |
| `CocoaPods not installed` | В этом проекте плагинов нет, но если Flutter всё равно требует: `brew install cocoapods` |
